# Prototype A — POS

Static reference only. The isolated surface represents Customer, search, Asset/barcode, invoice item, weight, making, VAT, Gift Voucher, payment, remaining due, total, disabled checkout, error and loading states. It preserves the existing Customer → Search → Items → Payment → Totals sequence and introduces no checkout, pricing, tax or payment behavior.

Visual response: one strong total panel, scan-friendly search, readable item identity, touch/keyboard-visible controls and explicit disabled/error/loading states. Functional behavior unchanged: no API, no mutation, no business action.
