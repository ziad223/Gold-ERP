# Responsive Strategy Proposal

Use content-priority adaptation rather than shrink-to-fit. Preserve primary Asset/invoice identity and primary action; move lower-priority fields to detail rows, drawers, or expandable sections; let long operational forms remain scrollable but visually group core/advanced fields. Tables should use responsive row details or a list/detail projection when mobile scanning is the real task. Sticky summaries must not cover inputs or totals.

Define breakpoints from observed content and test all seven project classes. Do not convert an existing business workflow into a wizard, add a second workflow, or change API/state behavior. Tablet and mobile POS must keep search, customer context, item identity, payment mode, total, and recovery visible and reachable.
