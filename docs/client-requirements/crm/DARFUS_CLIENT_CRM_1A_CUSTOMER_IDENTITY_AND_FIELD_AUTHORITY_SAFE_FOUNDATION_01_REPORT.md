## 1. Executive Summary

CRM-1A completed the customer identity and field-authority foundation with one minimum safe source correction: the API customer-list search now includes the canonical Customer ID. The correction changes only a read predicate; it does not change the Customer model, payload shape, persistence, permissions, branch/company rules, or any owning operational domain.

Sales, invoice, reservation, installment, gift voucher, CGP, credit, loyalty, timeline, attachment, audit, POS, and reporting domains retain ownership of their own records and references.

- `Customer.status` is a company/customer lifecycle state. `BranchCustomer.isActive` is relationship membership. They remain separate.

- `Customer.balance` is a reference value; credit movements are owned by `customer_credit_transactions` and statement/reconciliation services.
- `normalizePhone` is a duplicate-validation/comparison function, not a second stored identity.
- `addresses` is the Customer profile authority; invoice contact snapshots are immutable document evidence, not a CRM address owner.
- `loyaltyPoints` is a current read value; `LoyaltyTransaction` remains movement authority.

No field was deleted, renamed, merged, or duplicated.

## 11. Safe Changes Applied

### Corrected identity search gap

Before: `setupCrud("customers", models.Customer, ["name", "phone", "email"])`.

After: `setupCrud("customers", models.Customer, ["id", "name", "phone", "email"])`.

Root cause: the UI placeholder and local repository included ID search, but the API controller only searched the three contact fields. Runtime search for `CUS-0003` returned zero before the fix.

Safe result: runtime search for `CUS-0003` returned exactly one record in AR and one in EN, without changing the response shape or DB.
